# 官方评测平台操作手册（问题三）

> 适用：2026 CUMCM B 题问题三，程序 `T3.py`（确定性主线）。
> 本手册只讲**在官方测试平台上怎么跑**；算法与本地演练见 `README.md`。

## 0. 一句话说明

官方模拟器是 **Windows 桌面程序**（Wails + WebView2，Wine 下缺 WebView2 无法启动），
机器狗接口**只监听 127.0.0.1**。因此：**模拟器与程序必须在同一台 Windows 机器上运行。**

```
Windows 机器
├── 官方模拟器（jammers-simulator-full.exe）  监听 http://127.0.0.1:2026
└── Python + T3.py                            连 127.0.0.1:2026，跑完一局
```

`T3.py` **不带任何参数**就跑官方模式，结果写 `results/t3/`。

> **结果目录不按模式分家**：官方模式与本地演练写同一个目录，一个结果目录 = 最新一次运行。
> 跑完官方测试后，该目录里的演练批产物（多局统计、真值相关字段）会被这次单局结果覆盖。
> 想知道某个目录是哪一次运行留下的，看 `t3_survey.json` 的 `meta.mode`：
> `practice` / `official`。

## 1. 一次性准备（约 5 分钟）

### 1.1 模拟器

用**带运行时的 full 版**：`Jammers-simulator-full/jammers-simulator-full.exe`
（目录里的 `WebView2Runtime/` 是配套运行时；普通版要求系统已装 WebView2）。
解压后**整体保留目录结构**，模拟器会把登录与测试数据写进同级的 `JammersSimulatorData/`。
需要移动时整体移动。

### 1.2 Python 环境

1. 从 python.org 安装 **Python 3.14**（`pyproject.toml` 要求 `>=3.14`；勾选 *Add python.exe to PATH*）。
2. 安装依赖：

```powershell
pip install numpy matplotlib shapely
```

（`matplotlib` 只用于每局结束后的轨迹图，不装也能完成测试、只是不出图；`shapely` 只被问题二的
几何自检用到，不跑 `T2.py` 可以不装。）

### 1.3 拷贝程序文件

代码按包组织，需要**整个 `cumcm/` 目录 + 顶层入口**，放进同一个目录（例如 `D:\cumcm\`）：

```
T3.py         入口（确定性主线，正式测试用）
cumcm\        求解实现（common / t1 / t3 / t4 / analysis 五个子包）
```

`cumcm\` 少一层都不行：`T3.py` 只调用 `cumcm.t3.cli`，
`sim_api.py` 只是 `cumcm.common.sim_client` 的兼容垫片。
**不要**只拷 `sim_api.py` 和某个入口文件 —— 那样会报
`ModuleNotFoundError: No module named 'cumcm'`。

不需要拷贝 `jammers-py/`（本地演练用的复刻模拟器，官方平台上用不到）、不需要 `results/`、
`reports/`、`paper/`、`__pycache__/`。

拷贝后自检（在 `D:\cumcm\` 下执行）：

```powershell
python T3.py --help
python -c "import cumcm, cumcm.t3.cli; print(cumcm.__version__)"
```

能看到中文参数说明、并打印版本号即表示环境正常。若要把代码压成单文件交，见 1.4。

### 1.4 可选：打包成单文件

若平台只收单个 `.py`，用标准库 `zipapp` 把包和入口打成一个可执行文件：

```bash
# 在仓库根目录执行；产物是 build/submit.pyz
python -m zipapp . -m "cumcm.t3.cli:main" -o build/submit.pyz -p "/usr/bin/env python3"
python build/submit.pyz --help          # 自检
```

打包后仍是同一份代码、同样的随机行为（策略全程不依赖 `random`，用 `--seed` 完全可复现），
只是把 `cumcm/` 收进了一个 zip 里。注意打出来的文件要在**同一个工作目录**下运行，
`--save-dir` 等相对路径才与本地一致。

## 2. 演练测试：务必先跑通

正式测试每题**只有 3 次机会**，且中止也占用一次。所以先用**不限次数**的演练测试把流程走通。

### 2.1 流程图

```
① 双击 jammers-simulator-full.exe
② 联网登录（首次需注册）
③ 选「问题3演练测试」→ 点开始 → 二次确认
④ 5 秒倒计时（此期间接口未开放，先别运行程序）
⑤ 界面提示接口已就绪
⑥ 运行：python T3.py        （等价于 --base-url http://127.0.0.1:2026）
⑦ 约 3 秒后程序自行结束；界面「指令与反馈」区可见完整请求/反馈
⑧ 记下界面显示的清除结果，与本程序输出的「清除 N 个」核对
```

### 2.2 具体命令

```powershell
cd D:\cumcm

# 推荐写法：以 UTF-8 输出，中文与符号显示最干净。不带参数即连默认地址
python -X utf8 T3.py

# 若模拟器设置里改过端口（默认 2026）：
python -X utf8 T3.py --base-url http://127.0.0.1:8080

# 不连模拟器、只求解覆盖圆方案（可在任意机器上跑）：
python -X utf8 T3.py --plan-only
```

参数说明（一般都不用改）：

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `--base-url` | `http://127.0.0.1:2026` | 模拟器接口地址，改过端口才需要 |
| `--robot-id` | `202614023005` | 参赛队号，已内置，不用传 |
| `--save-dir` | `results/t3/` | 结果输出目录（不按演练/官方分家） |
| `--quiet` | 关 | 只打印汇总，不打印过程明细 |
| `--no-plot` | 关 | 关闭每局结束后的轨迹图 |

### 2.3 预期输出

（下例是**实测样例**：用与官方同源的复刻模拟器走同一套官方模式代码路径跑出来的，连同
`results/t3/` 的顶层内容一起留档，便于对照。）

```
==========================================================================
2026 CUMCM B 题 · 问题三：机器狗搜索与清除干扰源（确定性策略）
==========================================================================
连接模拟器 http://127.0.0.1:2026（robot_id=202614023005）
完成：清除 16 个，巡视 7 个圆心，里程 15489 m，虚拟时间 3864 s，测向 113 次（补测 2 次），听到 16 个频道（40 条示向度）
结果已保存：results/t3/t3_cover_plan.json，results/t3/t3_cover_circles.csv，results/t3/t3_survey.json，results/t3/t3_observations.csv
总轨迹图：results/t3/trajectory/ep01.png，results/t3/trajectory/ep01.csv
接口调用日志：共 138 次（/clear 11、/enter 1、/exit 1、/measure 125）→ results/t3/api_calls.jsonl
```

上面是 **T3.py（确定性主线）** 的实测样例（与 `results/t3/` 一起留档，便于对照）。

**核对要点**：本程序报的「清除 N 个」应与模拟器界面显示的清除结果一致；
`/enter`、`/exit` 各恰好 1 次；`/measure` 次数 = 测向次数。
注意「清除动作」次数会多于「清除」个数（上面例子 19 > 16）——多出来的几次是
`/clear` 返回 `no_target_in_range`（定位略有偏差），随后程序会沿实测示向度逼近重试，
这是正常策略行为，只多花虚拟时间（每次 3 秒）。

### 2.4 每局结束自动生成轨迹图

每跑完一局，程序会在 `<save-dir>/trajectory/` 下生成一张**总轨迹图**（官方模式名为
`ep01_official.png`，演练模式名为 `epNN_seedS.png`）和同名轨迹表；同时在
`<save-dir>/scan/` 下为**每一步扫描**各生成一张图（官方模式名为
`ep01_official_s00_起点全频道扫描.png`、`ep01_official_s01_…`）。
两个目录每次运行开头都会清空，因此始终只保留最新一次的图。，用来看清机器狗这一局怎么走的：行驶路径、每个测向点、每次清除尝试、成功清除落点，
以及干扰源真值及其 20 m 清除半径。

- 绘图在 `/exit` **之后**进行，**不占用 20 分钟现实时间预算**（单张约 1 秒）。
- 需要 `matplotlib`；**没装也不会影响测试**，只会提示一次并跳过绘图（`pip install matplotlib` 即可启用）。
- **官方模式的图上没有干扰源标记**：接口不返回真值，程序无从得知源在哪，所以图上只有
  行驶路径、测向点、清除尝试与成功清除落点。要看源的位置请用本地演练（`--practice N`）。
- **逐步扫描图** `scan/`：每张对应"机器狗停在某处把该测的频道测一遍"，标出本步测向点与
  结果（有示向度 / 无信号 / 近距）、示向度射线（长 1500 m，源必在该方向上）、到本步为止的
  行驶路径、当时的定位估计与累计清除数。总轨迹图看不清的细节（哪一步听到了什么、区域收缩
  到什么程度）在这些图里一目了然。

### 2.5 耗时

程序现实耗时约 **3 秒**（现实限时 1200 秒，余量极大）。
「虚拟总时间」是虚拟世界里的时间（约 4000~6000 秒），现实中不等待。

## 3. 正式测试

流程与演练完全相同，区别只有：

1. 在第 ③ 步选「**问题3正式测试**」，会有更明确的二次确认——确认后即占用一次机会。
2. 结果建议另存目录，便于区分：

```powershell
python -X utf8 T3.py --base-url http://127.0.0.1:2026 --save-dir results\formal
```

（官方模式与演练写**同一目录**，所以 `T3.py` 不加 `--save-dir` 写 `results/t3/`。）

3. 正式测试结束后，**导出模拟器生成的加密行为日志**（界面 4.6 节路径），
   连同本程序的 `results\formal\api_calls.jsonl` 一起作为支撑材料。

## 5. 常见问题

**Q：程序报 `连接模拟器失败：Connection refused`**
模拟器没启动，或端口不是 2026。先启动模拟器并确认已在测试中。

**Q：程序报 `连接模拟器失败：Remote end closed connection without response`**
模拟器在运行，但**接口未开放**——典型原因：5 秒倒计时还没结束，或测试已经结束。
等界面提示接口已就绪后再运行程序。

**Q：界面上点了开始，但忘了运行程序**
25 分钟窗口超时会自动结束并标记超时退出。演练无所谓；正式测试则会浪费一次机会。

**Q：中文显示为乱码**
用 `python -X utf8 T3.py`，或先在控制台执行 `chcp 65001`。
（程序已做兜底，即使字符编不出来也不会中断。）

**Q：能否在 Linux/Wine 上跑模拟器**
不行。实测 Wine 下报 `[WebView2 Error] no webview2 found`，窗口无法创建。
Linux 上的 `jammers-py` 是用于算法验证的复刻模拟器，**不能替代官方平台提交成绩**。

**Q：正式测试中网络抖动会不会中断**
机器狗接口是**本机回环连接**，不受外网影响。程序在异常时仍会尝试 `/exit`，
保证已清除的成绩有效；若接口整体关闭则本局结束。程序不自动重试，因此
**不要**在测试期间重启模拟器或切换网络。

## 6. 产出文件

跑完一局后 `results/t3/` 下会有：

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| `api_calls.jsonl` | 逐次 `/enter /measure /clear /exit` 的请求与原始响应 | **支撑材料**：题目要求程序自行记录指令序列与响应 |
| `trajectory/ep01.png` | 本局机器狗轨迹图 | 结果直观展示、论文插图 |
| `trajectory/ep01.csv` | 同名轨迹表（`step,x,y,kind`） | 与接口日志逐点对账 |
| `episodes.csv` | 本局战绩（清除数、虚拟时间、测向次数） | 论文与汇总表 |

官方模式下**拿不到干扰源真值**，因此定位误差等需要真值的指标留空——这是正常的，
成绩以模拟器判定为准。带真值的统计请用本地演练（`--practice N`，见 `README.md`）。
