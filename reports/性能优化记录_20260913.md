# 性能优化记录（2026-09-13）

本次优化的硬约束：**产物逐字节不变**。本项目的验收口径是"同一 seed 逐字节一致"（见 `AGENTS.md`），
所以任何改动都要先用"重跑 + 哈希对比"证明它不改结果，再谈速度；凡是会动到浮点末位或离散判据的
写法，一律否决并在原地留下说明。

计时环境：本机 Arch Linux / Python 3.14 / 16 核，**单进程、无其他负载**（早先几轮数字是在多个
批处理并行时测的，偏大且不可比，已废弃）。优化前的数字取自 `git worktree` 里的 `HEAD`
（`d27d864`）源码，与优化后的工作树用同一批命令、同一份输入。

## 改了什么

### 1. 问题二：定位四边形直径内核按批处理（`cumcm/t2/region.py`、`cumcm/t2/score.py`）

原来的 `worst_case_diameters` 对"源采样点 × δ₂"的 1395 个组合逐个调用 `quad_diameters`，每次
只算 41~712 个候选点；整套流程要 4.2 万次 `in_wedge` 调用，时间几乎全花在 numpy 调用开销上。

* 新增 `_candidate_points_batch` / `quad_diameters_batch`，`quad_diameters` 退化为 B = 1 的特例
  （原函数保留，两条路径共用同一套算式，故"批量前后逐元素一致"是构造上的保证）；
* θ₂ ± err 的单位向量只算一次（原先 (sa, sb) 四个组合里有两次是重复的）；
* `unit()` 增加标量缓存，`in_wedge` 改用 `_cos_sin`（不再 `np.stack`），`tol_deg = 0` 走无容差
  快路径；
* **批量大小是这一项的关键**：`score._COMBO_CHUNK_ELEMS` 从 150 000 降到 6 000 后，整套命令
  从 16.5 s 降到 12.3 s —— 批太大时 `(6, B, N)` 中间数组超出 CPU 缓存，元素处理反而变慢。
  实测：150 000 → 16.5 s、20 000 → 12.9 s、**6 000 → 12.3 s**、3 000 → 12.4 s、1 500 → 12.8 s。
* 全套 `in_wedge` 调用次数从 42 286 次降到 888 次。

### 2. 问题三：覆盖校验的距离内核（`cumcm/t3/covering.py`）

* `nearest_distances` 改为逐圆心一列、只比**平方距离**、最后只对 N 个最小值开一次方（开方单调，
  `√(min d²) = min √(d²)` 逐位相同），不再构造 `(N, 7, 2)` 三维临时数组、也不在轴长 2 的轴上做
  `np.linalg.norm` 的通用归约（那种归约实测慢数倍）；
* `cover_counts` 判据写成"平方距离 ≤ (r + TOL)²"（TOL = 1e-9 的余量在 d² 上是 2e-6，比浮点末位
  大七个数量级，逐点同判），省掉每次开方；
* `region_samples` 的圆域筛选同样改成平方距离。

三处都在 `-m cumcm.t3.covering` 里逐位核对过（细网格 42.7 万点、粗网格 4.9 万点）。

### 3. 问题四：听到率统计批量化（`cumcm/t4/sweep.py`）

`verify_hearing_stats` 有 422 万个算例，原先每个算例调一次 `_hit_report`（只算 20 个测量点），
时间全在 numpy 调用开销上。现在：

* 新增 `_hit_cases`（一批算例的命中掩码与命中深度，逐例与 `_hit_report` 同算式）与 `_scan_cases`
  （按**枚举顺序**分批扫描，保留"首个漏例"的口径）；
* 贴边对抗的算例集合抽成 `adversarial_cases`（按参数 `lru_cache`，布局搜索复用同一批算例）；
* 随机数抽取顺序、枚举顺序都不动，故 `n_cases` / `n_fail` / `worst_fail` 与逐例完全一致；
* 分块大小同样调过：200 000 → 2.8 s、50 000 → 2.2 s、**20 000 → 1.5 s**、5 000 → 1.6 s。

`-m cumcm.t4.sweep` 自检里加了"批量判据 vs 单例参考逐例一致"的对照（随机 200 个算例）以及
"`np.cos` 与 `math.cos` 在这批角度上逐位一致"的核验。

### 4. 布局搜索复用同一判决（`cumcm/t4/nn_layout.py`、`cumcm/t4/nn_layout_speed.py`）

这两个模块（`drv_speed.py` 的调参驱动）各自复制了一份"半圆盘命中"的逐例实现，GA 每代要评估上
百个候选布局。现在统一调用 `sweep._hit_cases` + `adversarial_cases`：`_edge_miss_fast` 从
108 ms/次降到 6.4~7.3 ms/次（约 15×），三个测试布局（含非零漏例）结果逐位一致。

### 5. 出图：补上漏掉的 `setup_mpl_env()`（`cumcm/t2/plotting.py`）

`draw_criteria` 在 `import matplotlib` 之前没调用 `setup_mpl_env()`，于是 `MPLCONFIGDIR` 没生效：
每次进程启动都会去扫 `/usr/share/fonts`（1502 次 `addfont`）、并打印
`/home/ylxc/.config/matplotlib is not a writable directory` 的警告（`MPLCONFIGDIR` 只在首次
`import matplotlib` 时读一次）。修掉后警告消失、字体缓存正常生效。

## 明确否决的写法（都试过、都量过）

| 写法 | 为什么不采用 |
| --- | --- |
| T2 直径点对改用平方距离、最后开一次方（快约 3 倍） | `hypot` 多做一次规格化，距离末位会变：`t2_second_site.json` 的 `134.08314207479023` → `...26`，与"逐字节一致"的验收口径冲突 |
| T2 `_max_pair_distance` 里"掩码全为假就跳过整个点对"（数学上确为空操作） | 多出的 `keep[i] & keep[j]` 布尔归约比省下的 hypot 更贵：21.5 → 24.0 ms/次（真实最大分块 6×210×712） |
| T2 `in_wedge` 把容差比较写成平方形式以省掉开方 | 收益 < 10%，却会动到"边界点算不算在内"的离散判据，风险与收益不匹配 |
| T4 统计里用 `np.cos/np.sin` 替换逐例 `math.cos/math.sin` 之外的任何近似 | 同上：容差 1e-9 处的判据是离散的 |
